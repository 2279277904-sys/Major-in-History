## 标准流程

统一从 `scripts/image_assets_cli.py grid-gif` 进入，不要临时拼接裁图、抠图和 GIF 命令：

```bash
python <skill-dir>/scripts/image_assets_cli.py grid-gif \
  --input /path/to/sprite-sheet.png \
  --output /path/to/animation.gif \
  --grid 4x4 \
  --duration 120 \
  --playback ping-pong \
  --anchor feet \
  --keep-frames
```

流水线按以下顺序执行：

1. 解析 `--grid 列数x行数`；只知道总帧数时用 `--frames N` 推断接近方形的布局。
2. 同时使用整行/整列均匀度和邻域颜色反差识别分隔线，剔除抗锯齿分隔带。
3. 对纯色背景执行保守连通换底；复杂背景改用 `rmbg2` 或 `birefnet`。
4. 清理接触画布边缘的细长线、空心框和孤立小噪点，不按深色相似度清理主体内部。
5. 过滤孤立连通组件，从前景底部 8% 检测双脚中心 X 和最低接地点 Y。
6. 把全部源帧的 X/Y 锚点对齐到统一画布；像素画缩放只用整数倍最近邻。
7. 按 `forward` 或 `ping-pong` 构建播放序列，使用共享调色板编码透明 GIF。
8. 生成清单、逐帧 PNG、棋盘格对齐检查板和最终 GIF 解码棋盘格预览。

## 关键默认值

### 抠图策略

- `--cutout-mode color`：纯色或近似纯色背景的像素素材默认值。
- `--background-tolerance 12`：深色背景和深色主体并存时的保守值。
- `#FF00FF`：内部唯一键色；只标记已经确认的边缘连通背景，然后精确设透明。
- `--alpha-feather 0`：像素画默认不羽化，避免轮廓发糊。
- `--cutout-mode rmbg2|birefnet`：纹理、照片、复杂渐变背景才使用模型。

不要因为背景有少量残留就先提高容差。先看残留是否是宫格分隔线抗锯齿；这类细线应由边界组件清理处理，而不是扩大颜色删除范围。

### 锚点策略

- `--anchor feet`：有站立角色时默认，同时对齐脚部中心 X 和最低接地点 Y。
- `--feet-ratio 0.08`：只取前景底部 8%，避免低垂尾巴或衣摆污染横向中心。
- `--anchor bottom-center`：没有稳定双脚，但主体下缘稳定时使用。
- `--anchor center`：悬浮物、旋转物或无明确地面接触点时使用。
- `--anchor cell`：只在必须保留原始格子坐标时使用；它不会修正角色在各格内的偏移。

### 播放策略

- `--playback forward`：源序列 `1 2 3 4` 循环为 `12341234...`。
- `--playback ping-pong`：编码 `1 2 3 4 3 2`，循环后形成 `1234321...`；不要重复编码首尾端点，否则每次折返会多停顿一帧。
- `--loop 0`：GIF 无限循环；与播放序列模式是两个独立概念。

## 输出与验收

`animation.gif` 旁必须出现：

- `animation.manifest.json`：记录切片、分隔带、背景策略、锚点、偏移、播放顺序和输出大小。
- `animation_alignment.png`：所有源帧的棋盘格检查板；红线是横向锚点，绿线是脚底。
- `animation_checker.gif`：从最终 GIF 重新解码后铺到棋盘格上的动画，验证编码后的真实透明区域。
- `animation_frames/`：传 `--keep-frames` 时生成的对齐后 RGBA PNG。

必须完成以下验收：

1. 逐格查看 `*_alignment.png`：红线应稳定穿过双脚之间，绿线应落在脚底；不能只重新调用同一个锚点函数后宣布通过。
2. 播放 `*_checker.gif`：主体内部不得出现棋盘格透明洞，衣裤等深色区域必须完整。
3. 检查四边和帧间空白处：不得残留青色分隔线、黑色细框或孤立像素。
4. 检查 manifest：`source_frame_count`、`frame_count`、`playback_order`、`background_tolerance` 和 `anchor` 必须符合命令意图。
5. 用 Pillow 重新打开最终 GIF，检查实际帧数、每帧 duration、loop 和透明角；不要只相信写文件前的内存对象。
6. 若怀疑 GIF 编码丢像素，逐帧比较最终 GIF 解码 alpha 与 `animation_frames/` 的 alpha；两者在阈值 128 下应一致。

## 失败模式与已否决方案

### 只按均匀度识别分隔线

深色空白列也可能非常均匀，会被误识别成几十像素宽的分隔带，导致格子裁窄。必须同时要求分隔线与邻域颜色存在明显反差，并在检查板中确认无分隔线残留。

### 只统一画布尺寸

统一画布只能消除格子尺寸不同造成的跳动，不能消除角色在格内的位置偏移。必须在抠图后对齐 X/Y 锚点。

### 把 AI 生成的九宫格误当成同一张背景的连续切片

AI 常会在每一格重新绘制看似相同的 HUD、霓虹线或纹理；即使格子等宽、角色位置相近，播放时背景仍会闪烁。切帧前先在每格边缘选取至少两个不被角色遮挡的背景锚点，测量它们到画布边缘的坐标：

- 锚点坐标有稳定平移差时，按同一背景锚点重新裁切或平移整帧，再生成 GIF；不要只凭格子尺寸相等就导出。
- 两个锚点无法被同一平移同时对齐时，说明背景内容本身是独立重绘，**单点锚定只能减少位移，不能消除背景闪烁**；不得宣称已经完成背景对齐。
- 这时应回到素材生成阶段，要求所有帧使用同一张静态背景底板，或先获得透明角色帧再叠加到共享底板。不要在导出阶段擅自重绘、替换或模糊背景；除非用户明确同意这种视觉改动。

交付前播放最终 GIF，逐帧观察两个背景锚点；任一锚点仍跳动或背景纹理闪烁时，先说明素材限制和可行重做路径，不能用“锚点误差”代替视觉验收。

### 用前景底部 15% 直接算脚中心

低垂尾巴、衣摆和宫格边缘噪点会进入底部区域，使横向锚点跳动数十像素。先过滤孤立组件，再把脚部区域收窄到前景底部 8%。

### 用同一算法自检锚点

错误锚点经过对齐后，再用同一算法检测仍会得到“完全一致”，这是自证循环。必须生成带参考线的逐帧检查板并目视验证角色主体。

### 在暗色检查板上验收深色主体

透明洞会与暗色背景融为一体，衣裤误删可能看起来正常。对齐检查板必须使用明暗棋盘格；还要从最终 GIF 解码生成 `*_checker.gif`。

### 将背景容差提高到 20 以上

深蓝背景与黑色衣裤的颜色距离可能很近。容差 20–24 会让边缘连通洪水填充穿进主体，形成衣服和裤子的透明洞。默认使用 12；需要调整时逐档生成棋盘格对比。

### 双阈值渐进扩张换底

“严格背景种子 + 较宽扩张阈值 + 单步颜色平滑”看似能覆盖渐变背景，但暗色轮廓到衣物也可能形成连续的小色差链，扩张仍会穿进主体。该方案已经实测否决，不要重新启用；使用保守连通换底加边界组件清理。

### 只检查中间 PNG，不检查最终 GIF

GIF 使用索引色和单一透明索引，中间 PNG 正常不能证明最终编码正确。必须检查从最终文件解码得到的棋盘格动画，必要时比较 PNG/GIF alpha。

## 跨环境恢复

新电脑只需 Python 3；纯色背景 `grid-gif` 首次运行会在 Skill 目录的 `.venv` 自动安装经过验收并按 Python 版本锁定的 Pillow / NumPy。Python 3.14、3.13 与更早版本分别选择当前有官方 wheel 的兼容组合，避免把旧版 NumPy 拉入本地源码编译。模型抠图才会额外安装 PyTorch、Transformers 等大依赖。

```bash
python <skill-dir>/scripts/image_assets_cli.py grid-gif --help
python <skill-dir>/scripts/image_assets_cli.py grid-gif \
  --input /path/to/sprite-sheet.png \
  --output /path/to/animation.gif \
  --grid 4x4 \
  --playback ping-pong \
  --anchor feet \
  --keep-frames
```

若 Skill 安装目录只读，设置 `IMAGE_ASSETS_VENV=/可写路径/venv`。完整环境变量和模型恢复方式见 `references/environment.md`。
